# Aster — план дальнейших доработок

Статус на момент составления: **v0.11.1**. Приложение стабильно, этапы 1–7 завершены, добавлены проверка стиля Markdown, GitHub Alerts и форматирование выделения, 65 тестов проходят. Этот файл — не список текущих багов, а backlog на будущее. Пункты можно брать по одному, не нарушая текущее поведение.

## Принципы

- Не ломать существующие сценарии: вкладки, сессия, поиск/замена, preview, хоткеи, recovery.
- Каждое изменение сопровождается тестами и проверкой на больших файлах из `/tmp/a-tests`.
- README.md и README_en.md обновляются синхронно.
- Крупные изменения делаются отдельными этапами с визуальным чек-листом.
- Для релиза: обновить `VERSION`, `Cargo.toml`, `Cargo.lock`, собрать архив и проверить SHA-256.

## P1 — надежность и сохранность данных

### 1. Recovery для изменённых файловых вкладок

Сейчас `recovery.json` покрывает только безымянные вкладки. Если изменить существующий файл, не сохранить и убить процесс, сессия восстановит версию с диска.

Что сделать:

- сохранять черновики всех документов с `is_modified = true`;
- хранить `path`, содержимое, позицию курсора и время изменения;
- при восстановлении открывать файловую вкладку с несохранённым содержимым и явной пометкой конфликта;
- не перезаписывать файл на диске автоматически;
- предусмотреть очистку recovery после успешного сохранения и штатного выхода.

Критерии готовности:

- `kill -9` после правки существующего файла не теряет текст;
- после перезапуска видно, что вкладка содержит несохранённую версию;
- выбор «Сохранить»/«Перезагрузить» ведёт себя предсказуемо.

### 2. Удаление и переименование файла

Сейчас события `Deleted` / `MovedOut` игнорируются.

Что сделать:

- показывать toast «Файл удалён или перемещён»;
- предлагать «Сохранить как…»;
- не терять содержимое буфера;
- при переименовании, если новый путь можно определить, предложить продолжить работу с ним.

### 3. Ограничения FileMonitor

Проверить и описать поведение на:

- сетевых ФС (NFS, SMB);
- атомарных сохранениях сторонних редакторов;
- файлах, заменённых через `mv`/`rename`;
- очень частых внешних изменениях.

При необходимости добавить fallback-опрос `mtime`/размера с большим интервалом.

## P1 — архитектура

### 4. Разбить оставшиеся крупные файлы

Сейчас:

- `src/window.rs` — ~1170 строк;
- `src/document/mod.rs` — ~1283 строки.

Предлагаемое разбиение:

- `src/window/workspace.rs` — startup, добавление вкладок, close-flow;
- `src/window/header.rs` — заголовочные кнопки и их синхронизация;
- `src/document/view.rs` — построение UI вкладки;
- `src/document/preview.rs` — WebView, загрузка HTML, ссылки;
- `src/document/scroll.rs` — память прокрутки и восстановление позиций.

Критерии готовности:

- ни один файл не превышает ~800–900 строк;
- поведение не меняется;
- тесты проходят без правок логики.

### 5. Единый контекст окна

Часть замыканий в `window.rs` повторяет одинаковые клоны `Rc`/виджетов. Можно ввести `WindowContext` с полями:

- `window`, `tab_view`, `docs`, `settings`;
- `persist_session`, `refresh_active_ui`, `add_document`;
- `toast_overlay`, `show_toast`;
- `closed_tabs`, `recovery`.

Это уменьшит количество захватов и риск циклов владения.

## P2 — поиск, preview и производительность

### 6. Подсветка всех совпадений без просадки

Сейчас при более чем 200 совпадениях подсвечиваются первые 200: каждый `TextTag` применяется отдельно и на тысячах вхождений это медленно.

Варианты:

- подсвечивать только видимую область и обновлять при прокрутке;
- виртуализировать диапазоны;
- оставить лимит настраиваемым;
- проверить `GtkSourceView`-подобные подходы.

Критерии:

- счетчик и навигация по всем совпадениям;
- отсутствие заметной задержки на 5000+ вхождений;
- текущее совпадение всегда видно.

### 7. Preview-поиск через несколько DOM-узлов

Сейчас поиск идет по отдельным текстовым узлам. Фраза, разбитая inline-разметкой, может не найтись.

Что сделать:

- обходить текст в пределах блока через `Range`/`TreeWalker`;
- сопоставлять позиции с глобальным текстом;
- сохранить подсветку через `<mark>` и навигацию.

### 8. Очень большие файлы

Проверить на файлах 10–50 МБ:

- открытие;
- переключение editor/preview;
- Replace All;
- подсветку Markdown;
- gutter.

Возможные улучшения:

- инкрементальный preview;
- ленивая подсветка видимых строк;
- ограничение истории undo;
- фоновая подготовка HTML.

### 10. Недавние файлы

- очистка списка;
- открытие папки файла.

### 11. Настройки редактора — ✅ реализовано в v0.7.3

- **Ширина табуляции** (1–8, по умолчанию 2) — отображение существующих символов `\t`; пересчитывается при смене шрифта.
- **Размер отступов** (1–8, по умолчанию 2) — количество пробелов, которое вставляют `Tab` и `Shift+Tab`. Табы в текст не вставляются.
- **Мягкий перенос строк** — по умолчанию включен; при отключении появляется горизонтальная прокрутка.
- **Показ пробелов и табов** — по умолчанию включен: пробелы рисуются точками, табы — горизонтальными линиями.
- Прозрачный слой отрисовки не меняет буфер, не перехватывает мышь и учитывает gutter, шрифт, его размер и тему.
- Настройки применяются ко всем открытым вкладкам сразу и сохраняются в `settings.json`.
- Догоняющие исправления: видимость слоя при отрицательном `visible_rect`, координаты с учетом gutter, размер шрифта gutter как у текста.
